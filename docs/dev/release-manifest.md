# Release manifest + `caelo-ops` image

Epic #696 ("one-click Caelo") installs and upgrades from inside the
product. Two release artifacts make that safe; this page is for
contributors touching either. The maintainer-facing rules (release-cut
inputs, security flag) live in [`RELEASING.md`](../../RELEASING.md#release-manifest).

## The `caelo-ops` image

`packages/provisioning/Dockerfile.ops` packages the provisioning CLI
with every tool it shells out to:

| Tool | Pinned by | Verified by |
|---|---|---|
| Bun | base image `oven/bun:<BUN_VERSION>-slim` | image tag |
| Node | `node:<version>-bookworm-slim` (same pin as the admin image) | image tag |
| Pulumi CLI | `PULUMI_VERSION` | `sha256sum -c` against `PULUMI_SHA256_<ARCH>` |
| cosign | `COSIGN_VERSION` | `sha256sum -c` against `COSIGN_SHA256_<ARCH>` |
| gcloud (+ beta) | `GCLOUD_VERSION` + exact apt pool file | `sha256sum -c` against `GCLOUD_SHA256_<ARCH>` (from the apt `Packages` index) |

- Multi-arch (amd64 + arm64). Bun only runs in a builder pinned to
  `$BUILDPLATFORM`, so it never executes under QEMU
  (oven-sh/bun#15044). The build fails if a native addon ever enters the
  provisioning closure, because the cross-arch copy would then be wrong.
- Runs as the non-root `caelo` user; entry point `caelo-ops` (also on
  PATH as `cms-provision`).
- `release-images.yml` boot-smokes it on every PR: `caelo-ops --version`
  must print the repo version, and node / pulumi / cosign / gcloud /
  `gcloud beta` must start.

Not in the image yet: Pulumi provider plugins (`pulumi-resource-gcp`
etc.) — they download on first `pulumi up`, as on a laptop.

## The manifest

Schema: `ReleaseManifestSchema` in
`packages/provisioning/src/release-manifest.ts` (`manifestVersion: 1`).
A new field means a new `manifestVersion`, so an old upgrader refuses a
manifest it cannot fully read instead of ignoring the new fact.

Generated by `scripts/release-manifest.ts generate` in `release.yml`
from:

- the digests of `admin`, `gateway`, `ops` at the version tag;
- `release-meta.json` — the declaration `scripts/release.ts` wrote at
  release cut (`security`, `advisories`, acknowledgements);
- `scripts/release-checks.ts` — re-runs the advisory, migration-lint and
  infra-contract rules against the previous stable tag;
- `packages/provisioning/src/infra-contract.ts` — `INFRA_CONTRACT_VERSION`
  (the same number `needsConverge` in `upgrade/converge.ts` compares
  against `install.json`);
- `packages/provisioning/src/release-contract.ts` —
  `RELEASE_MIN_FROM_VERSION`, `INFRA_CONTRACT_PATHS`.

### Trust chain

1. `cosign sign-blob` in `release.yml`, keyless. Fulcio binds the
   signature to `https://github.com/caelo-cms/caelo-cms/.github/workflows/release.yml@refs/tags/v<version>`.
2. The OCI artifact `release-manifest:<version>` holds the manifest and
   its Sigstore bundle as **layers**. The signature therefore survives
   any registry copy (no OCI referrers involved — compare the
   `oras copy -r` note in `release-images.yml`).
3. `fetchVerifiedReleaseManifest(version)` reads the artifact from the
   fixed AR mirror, checks each blob against its digest, runs
   `cosign verify-blob` with the **exact** identity for that tag (no
   regexp), schema-validates, and checks `manifest.version === version`
   (no replay of an older signed manifest).
4. `compareImageDigests(manifest, resolved)` — the digests a registry
   serves for the tags must equal the signed ones.
5. `assessAutoInstall(manifest, installed)` — `auto` / `manual` /
   `refused`, with reasons:

| Condition | Result |
|---|---|
| not newer than installed | `refused` |
| installed below `minFromVersion` | `refused` |
| `infraContractVersion` above the installed one | `manual` (Cloud Shell) |
| `migrations.contract` | `manual` |
| installed below `migrations.lastContractVersion` (skips a contract release) | `manual` |
| otherwise | `auto`, `kind: "security"` only when `security: true` |

A security release that is `manual` reports `kind: "normal"`, so an
"auto-install security fixes" policy can never apply it unattended.

### Usage

```ts
import {
  assessAutoInstall,
  compareImageDigests,
  fetchVerifiedReleaseManifest,
} from "@caelo-cms/provisioning";

const r = await fetchVerifiedReleaseManifest("0.11.0");
if (!r.ok) throw new Error(`[${r.error.code}] ${r.error.message}`);
const mismatches = compareImageDigests(r.manifest, { admin: resolvedAdminDigest });
const plan = assessAutoInstall(r.manifest, { version: "0.10.43", infraContractVersion: 1 });
```

Tests inject `fetch` and the `cosign` runner (`ReleaseManifestDeps`);
see `release-manifest.test.ts` for an in-memory registry fixture.

### Local commands

```bash
bun scripts/migration-lint.ts                     # contract migrations since the last stable tag
bun scripts/release.ts patch --checks-only        # every release-cut rule, no changes
bun scripts/release-manifest.ts verify --version 0.11.0   # needs cosign + network
```
